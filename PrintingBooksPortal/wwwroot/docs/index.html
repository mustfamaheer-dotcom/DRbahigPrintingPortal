Σ Overview

The DR. Bahig Printing Portal is a full-stack web application that enables bookshops to securely view, manage, and print PDF books that are assigned to them by an administrator. Every page rendered in the browser is dynamically watermarked with the shop's identity to prevent unauthorized distribution of the original PDF content.

The system follows an agent-based printing architecture: a lightweight local Windows service (the "Print Agent") runs on each shop's computer, polls the central server for pending print jobs, downloads encrypted PDFs, decrypts them locally, applies user-configured print settings, and sends them to a physical printer via SumatraPDF. This avoids exposing raw PDF files to the browser and allows the server to remain stateless with respect to physical printing hardware.

📡 Web Portal ASP.NET Core 10

Hosted on RunASP.NET. Blazor Server UI with role-based access (Admin / Shop). Serves watermarked PDFs to authorized users, manages assignments, logs prints, and queues jobs for the local agent.

🖥️ Print Agent Kestrel + SumatraPDF

Windows console app running as a scheduled task. Polls the portal for pending jobs, downloads encrypted PDFs via API key authentication, decrypts, applies settings (margins, scaling, orientation), and prints via SumatraPDF CLI.

📀 Database SQL Server / SQLite

Dual-provider EF Core. SQL Server in production (RunASP.NET), SQLite for local development. Includes Identity tables for auth, business tables for shops/books/assignments, and audit logging.

📱 System Tray UI Windows Forms

Optional desktop companion with NotifyIcon and dashboard form. Provides health status, printer list display, and agent start/stop controls for shop staff.

🔧 System Architecture

The system uses a server-agent-polling pattern rather than server-push, because the agent runs on a local network behind NAT without a public endpoint. The portal exposes a REST API that the agent polls at a configurable interval.

┌──────────────┐ ┌──────────────────────┐ ┌─────────────────┐ │ Browser │ │ PORTAL (ASP.NET) │ │ AGENT (Win) │ │ (Chrome/Edge)│ │ runasp.net:443 │ │ localhost:8080 │ └──────┬───────┘ └──────────────────────┘ └────────┬────────┘ │ │ │ │ 1. GET /view-secure │ │ │◄──── watermarked base64 ──►│ │ │ │ │ │ 2. POST /process-print │ │ │◄──── { jobId, success } ──►│ │ │ │ │ │ │ 3. GET /pending (3s loop) │ │ │◄───────────────────────────►│ │ │ 4. POST /claim/{jobId} │ │ │◄───────────────────────────►│ │ │ 5. GET /download-secured │ │ │◄──── encrypted PDF ────────►│ │ │ │ │ │ │ 6. Decrypt + resize + print │ │ │ SumatraPDF → 🖨

Component Roles

🌐 Portal (Server)

  • Authenticates users (Admin/Shop roles)
  • Serves watermarked PDFs via base64 to browser
  • Encrypts PDFs with AES-128 per-print-job password
  • Maintains in-memory ConcurrentDictionary job queue
  • Broadcasts job events via SignalR
  • Logs all print activity to SQL Server

💻 Agent (Local Client)

  • Kestrel web server on localhost:8080
  • Background polling loop (configurable interval)
  • Authenticates with X-Api-Key header
  • Decrypts PDFs using shared OwnerPassword
  • Applies margins, scaling, orientation via iText7
  • Spawns SumatraPDF CLI for physical print

📝 Browser (Client)

  • Renders PDF.js viewer with watermarked pages
  • Collects print settings (printer, paper, margins, etc.)
  • Submits print job via REST API
  • Polls agent health on 127.0.0.1:8080
  • Receives SignalR status updates on job progress

📀 Database (SQL Server)

  • Persists shops, books, boards, assignments
  • Stores Identity users and roles
  • Audits all print operations in PrintLogs
  • Stores system settings (watermark toggles)
🔗 The agent polls every 3 seconds. Jobs expire from the queue after 5 minutes if not claimed. A StaleJobMonitor background service reverts Processing jobs older than 2 minutes back to Queued.

🔄 Print Pipeline — Full Data Flow

From the moment a shop user clicks Print in the browser to the physical paper emerging from the printer:

// ── PHASE 1: BROWSER ──
pdfViewer.js -> checkAgentHealth()  GET  http://127.0.0.1:8080/api/print-job/health
              -> readPrintSettings()   Read printer, paper, margins, scaling, copies
              -> submitPrintJob()      POST /api/pdf/process-print  { bookId, settings }

// ── PHASE 2: PORTAL ──
SecurePdfController.ProcessPrint()
  1. Validate user has access to book
  2. Read original PDF from App_Data/Books/
  3. Apply watermark: WatermarkService.ApplyWatermark()
     // Diagonal "LICENSED TO: {ShopName}" on every page
  4. Encrypt: PdfSecurityService.EncryptPdfWithPassword()
     // AES-128, user pass = "PRINT-{jobId}", owner pass = shared
  5. Save encrypted PDF to SecurePrints/{jobId}.pdf
  6. Log to PrintLogs table
  7. Add to PendingPrintJobs ConcurrentDictionary
  8. Broadcast via SignalR to PrintAgents group
  9. Return { jobId, added, queueCount }

// ── PHASE 3: BROWSER POLLING ──
pdfViewer.js ->  Poll GET /api/pdf/print-agent/pending (10x, 2s apart)
              ->  If jobId absent from response = agent claimed it
              ->  Show "Success" or "Timeout" modal

// ── PHASE 4: AGENT ──
Agent Polling Loop (every 3s)
  - GET /api/pdf/print-agent/pending  (header: X-Api-Key)
  - POST /api/pdf/print-agent/claim/{jobId}

PdfPrintService.DownloadAndPrintAsync(jobId)
  1. GET /api/pdf/download-secured/{jobId}  → encrypted PDF bytes
  2. Decrypt using OwnerPassword
  3. ApplyPdfSettings():
     - Create new PDF at target PaperSize
     - For each page: scale (actual/fit/custom), apply margins, center
  4. Save debug copy: logs/pre_{jobId}_{timestamp}.pdf
  5. For each copy:
     - Spawn SumatraPDF-3.6.1-64.exe
       args: "-print-to \"{Printer}\" -print-settings \"noscale,duplexvertical\" -silent \"{tempFile}\""
  6. Clean up temp file (5s delay)
  7. Release job on failure: POST /api/pdf/print-agent/release/{jobId}
⚠️ Orientation handling: ApplyPdfSettings swaps page width/height when landscape is selected (creating landscape-sized pages). SumatraPDF additionally receives landscape in -print-settings to inform the Windows printer driver of the intended paper orientation. Both layers are required for correct output.

🔒 Security Model

Authentication

ASP.NET Core Identity with cookie-based auth. Two roles:

  • Admin — Full access: manage shops, books, boards, users, settings, analytics
  • Shop — Limited to assigned books, print history, and the PDF viewer

Password policy: minimum 6 characters, requires digit. Cookie: HttpOnly, Secure, SameSite=Strict, 8-hour sliding expiration.

API Key (Agent)

Agent endpoints are protected by X-Api-Key header validation:

  • Admin sets the key in AgentSettings:ApiKey
  • Agent includes it in every request to the portal
  • Validated by IsValidAgentApiKey() on each endpoint
  • Fallback to cookie auth when API key is absent (for browser testing)

PDF Encryption

AES-128 encryption per job:

  • User password: PRINT-{jobId} — unique per job, one-time download
  • Owner password: Shared secret known only to the agent
  • Encrypted file deleted from disk after first download

Watermarking

Every page served to the browser is watermarked:

  • Text: "LICENSED TO: {ShopName} | User: {UserName} | {Timestamp}"
  • Diagonal rotation (-45°) across the page center
  • Rendered via PdfSharpCore XGraphics
  • Can be toggled off globally in Admin Settings

Anti-Forgery & CSRF

  • Global antiforgery via app.UseAntiforgery()
  • Blazor Server handles CSRF via SignalR circuit
  • Only /api/login explicitly opts out with [IgnoreAntiforgeryToken]

Download Security

  • Encrypted print files served via PhysicalFileResult with FileDownloadName
  • File deleted immediately after SendFileAsync completes
  • One-time download: subsequent requests return 404

🖥️ Local Print Agent

The BookShopPrintAgent is a .NET 10 console application that runs as a Windows scheduled task (SYSTEM level). It hosts a Kestrel web server on http://localhost:8080 and runs a background loop that polls the portal for pending print jobs.

Startup Sequence

// Program.cs entry point
1. Kill any existing process on port 8080
2. Configure Kestrel on http://localhost:8080
3. Register HttpClientFactory + PdfPrintService in DI
4. Start background loop:
   PollingLoop:
     a. GET  {BaseUrl}/api/pdf/print-agent/pending
     b. POST {BaseUrl}/api/pdf/print-agent/claim/{jobId}
     c. DownloadAndPrintAsync(jobId)
     d. Sleep 3 seconds

PdfPrintService Flow

DownloadAndPrintAsync(jobId)
  ├─ GET /download-secured/{jobId}      // encrypted PDF bytes
  ├─ Decrypt (iText7, OwnerPassword)
  ├─ ApplyPdfSettings():
  │   ├─ Create new PDF at target PaperSize
  │   ├─ For each page:
  │   │   ├─ Scale (actual/fit/shrink/custom %)
  │   │   ├─ Apply margins (top/bottom/left/right)
  │   │   └─ Center on page
  │   └─ Save debug: logs/pre_{id}_{ts}.pdf
  ├─ For each copy:
  │   └─ SumatraPDF: -print-to "{printer}" -print-settings "noscale,landscape" -silent "{file}"
  └─ Clean up temp file (5s delay)

Printer Detection

Uses WMI SELECT * FROM Win32_Printer. Returns printer name, status, online state, connection type (USB/Network/Bluetooth/WiFi/Local), driver, and location. Virtual printers (PDF, OneNote, XPS, Fax) are excluded from results.

📖 PDF Viewer (pdfViewer.js)

The pdfViewer.js (829 lines) is the core frontend client. It is a self-executing anonymous function that manages the entire PDF viewing and printing experience.

Key Capabilities

🔒 Security Measurements

  • Disables context menu
  • Blocks keyboard shortcuts: Ctrl+S, Ctrl+P, F12, Ctrl+Shift+I/J/C
  • Disables drag/select inside PDF container

🖼️ PDF Rendering

  • Loads pdf.min.js (Mozilla PDF.js)
  • Fetches watermarked PDF as base64 from /api/pdf/view-secure/{bookId}
  • Decodes to Uint8Array, renders with PDF.js
  • Lazy page rendering via IntersectionObserver

⚙️ Print Settings

  • Printer selection via agent health endpoint
  • Paper size (A4/A3/A5/Letter/Legal/Tabloid + custom)
  • Orientation (Portrait/Landscape), Scaling (actual/fit/custom)
  • Margins (Normal/Narrow/Custom presets)
  • Margin pixel conversion: 1 mm = 3.78 px, 1 in = 96 px

🖨 Print Flow

  • Checks agent health at http://127.0.0.1:8080/api/print-job/health
  • POSTs to /api/pdf/process-print with all settings
  • Connects to SignalR /hubs/print for real-time status
  • Polls pending queue as fallback (10 attempts, 2s intervals)
  • Shows progress/success/error Bootstrap modals
