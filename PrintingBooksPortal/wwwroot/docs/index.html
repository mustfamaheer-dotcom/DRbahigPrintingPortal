Project Overview

What Is PrintingBooks Portal?

PrintingBooks Portal is a full-stack web application purpose-built for managing educational book printing across a distributed network of bookshops. It acts as a central command centre that connects publishers, educational boards, and printing shops under one unified platform. The system handles the entire lifecycle of educational book distribution — from uploading digital textbooks and organising them by curriculum board, to assigning access rights to specific shops, to enabling secure on-demand printing with copyright protection.

Built with ASP.NET Core 10.0 (Blazor Server) and Entity Framework Core, the system serves two distinct audiences: administrators who manage the platform and control access, and shop users who browse assigned books and send them to print. Every print operation passes through a multi-layered security pipeline that watermarks each page with the shop's identity, encrypts the PDF with a per-job password, and logs every detail for auditability.

The project consists of three software components that work together:

ComponentPlatformPurpose
PrintingBooksPortal (Web Server)ASP.NET Core 10.0 — Blazor Server + Web APIThe main web application that hosts the admin and shop interfaces, REST APIs, PDF security services, and the database layer. Deployed on RunASP.net hosting.
BookShopPrintAgent (Desktop Agent).NET 10.0 Console ApplicationA lightweight Windows agent installed on each shop's local machine. It polls the server for pending print jobs, downloads encrypted PDFs, decrypts them, and sends them to a local printer via SumatraPDF.
BookShopPortalUI (Legacy Desktop App)WPF (.NET Framework)An older Windows desktop client that is no longer actively used. Retained for reference purposes.

The Problem It Solves

Educational book distribution faces a fundamental challenge: how to provide printing shops with access to digital textbooks while preventing unauthorised copying and distribution. Before this system, the workflow was fragmented — books were shared via email or USB drives, there was no tracking of who printed what, and copyright protection was practically non-existent. Administrators had no visibility into which shops were printing which books or how many copies were being produced.

PrintingBooks Portal solves this by providing:

  • A centralised digital library where books are stored once and accessed by many shops, eliminating file duplication and version chaos.
  • Granular access control so administrators decide exactly which shops can access which books, with the ability to revoke access instantly.
  • Per-page forensic watermarking that embeds the shop name, user identity, and timestamp onto every printed page, making leaked copies traceable back to their source.
  • Password-protected print jobs that encrypt the PDF before transmission, ensuring only authorised agent software (not a browser) can decrypt and print the file.
  • Complete audit trails that record every print operation — who printed what, when, from which shop, how many copies, and from which IP address.

How the System Works (End-to-End Flow)

The following describes a typical workflow from the perspective of an administrator and a shop user:

#StepActorDescription
1Create Educational BoardsAdminThe administrator defines curriculum boards (e.g. "Cambridge IGCSE", "Edexcel International", "IB Diploma"). These serve as categories for organising books.
2Upload BooksAdminThe administrator uploads PDF textbooks, assigns each to a board, and sets metadata (title, page count). The file is stored securely in the server's file system with a GUID-based filename to prevent direct URL guessing.
3Register ShopsAdminThe administrator creates shop records with contact details (name, address, phone). Each shop represents a physical bookshop that will print and sell books to students.
4Assign Books to ShopsAdminThe administrator selects which books each shop is allowed to access. This is a many-to-many relationship — a book can be assigned to many shops, and a shop can access many books. Assignments can be toggled on/off at any time.
5Create Shop User AccountsAdminThe administrator creates user accounts for each shop's staff. Each user is linked to their shop and granted the "Shop" role, scoping their access to only their shop's assigned books.
6Browse & View BooksShopShop staff log in and see only the books assigned to their shop. They can view any book in a secure in-browser PDF viewer that applies a live watermark overlay (shop name, user name, date/time).
7Initiate a Print JobShopThe shop user selects a book, specifies the number of copies (1-50), and submits a print request. The server watermarks the PDF, encrypts it with a unique per-job user password and a global owner password, saves the encrypted file, logs the operation, and adds the job to the pending queue.
8Agent Polls & PrintsAgentThe BookShopPrintAgent running on the shop's Windows machine polls the server every 3 seconds. When it finds a pending job, it claims it (removing it from the queue), downloads the encrypted PDF, decrypts it using the shared owner password, and sends it to the default printer via SumatraPDF. The encrypted file is deleted from the server after download.
9Review AnalyticsAdminThe administrator monitors print activity through the analytics dashboard, which shows per-shop totals, daily/weekly trends, and a detailed log of the most recent 50 print operations.

PrintingBooks Portal delivers tangible value to educational book distribution networks:

Operational EfficiencyCentralised book management eliminates the need to physically ship textbooks or share files via unsecured channels. One upload serves all shops.
Audit ReadinessComplete print logs provide publishers and administrators with concrete usage data for royalty calculations, compliance reporting, and inventory planning.

Security Architecture

The system implements a multi-layered security model to protect educational content from unauthorised distribution.

Security Layers

1
Authentication
ASP.NET Core Identity with cookie auth. HTTPS-only, HttpOnly, SameSite=Strict cookies. 8-hour sliding expiration.
2
Authorization
Role-based with Admin and Shop policies. Shop users scoped to their assigned books only.
3
Watermarking
Every PDF view or print includes a diagonal overlay: shop name, user, timestamp. Configurable via admin settings.
4
Encryption
Print jobs are AES-128 encrypted with per-job user password + global owner password. Only printing permission is granted.
5
Audit Trail
Every print operation is logged with shop, book, copies, user, IP address, and timestamp.
6
Transport
HTTPS enforced in production. HSTS enabled. X-Forwarded-Proto trusted behind RunASP.net load balancer.

Print Flow Security

  Shop User                    Server                        Agent
     |                          |                             |
     |-- POST /process-print -->|                             |
     |                          |-- Encrypt PDF (AES-128)     |
     |                          |-- Store SecurePrints/       |
     |                          |-- Log print audit           |
     |<-- { jobId } ------------|                             |
     |                          |                             |
     |                          |<-- GET /pending (poll 3s) --|

     |                          |                             |

     |                          |-- { success, copies } ----->|
     |                          |                             |
     |                          |<-- GET /download-secured ---|
     |                          |-- encrypted PDF bytes ----->|

     |                          |          [Decrypt with      |
     |                          |           owner password]   |
     |                          |          [Print via         |
     |                          |           SumatraPDF]       |

The agent never sees the owner password in logs — it is read from config only. The encrypted PDF is deleted from the server after download (one-time access).

Print Agent (Desktop Client)

The BookShopPrintAgent is a Windows desktop agent that runs on each shop's local machine. It polls the central server for pending print jobs, downloads encrypted PDFs, decrypts them, and sends them to a local printer.

How It Works

StepAction
1Agent starts, configures Kestrel on http://localhost:8080
2Background task polls GET /api/pdf/print-agent/pending every 3 seconds
3When a job is found, agent claims it via POST /claim/{jobId}
4Agent downloads encrypted PDF via GET /download-secured/{jobId}
5Agent decrypts PDF using the owner password (iText7)
6Agent spawns SumatraPDF with -print-to arguments for each copy
7Temp file is deleted after 5-second delay

Based on a full codebase audit, the following improvements are recommended, prioritised by impact and urgency.

Critical (Security & Stability)

3Raw SQL DDL in settingsServices/SettingsService.cs (lines 183-220)Replace inline CREATE TABLE SQL with proper EF Core migrations.
4In-memory print queueControllers/SecurePdfController.cs — PendingPrintJobsImplement database-backed print queue with status tracking (Pending, Claimed, Printing, Completed, Failed).

Medium (Architecture & Quality)

#IssueRecommendation

6Zero test coverageAdd xUnit + integration tests for PDF pipeline, auth flows, API endpoints

8Analytics queries unscalableAdd pagination, materialized views, or read replica for large datasets
